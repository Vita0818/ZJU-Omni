# 工具设计原则

加新平台或新工具时照这几条做。lite 规则来自本地模型实测（见 [lite-eval.md](lite-eval.md)）。

## 两个版本都适用

1. **确定的结果在服务端算好。** 合计、排序、合并多个来源、换算时区和星期、算剩余时间、判断“当前学期”“最近一节”“最早截止”这类有唯一答案的事，由代码算完直接返回结果字段，不交给模型推算。模型只负责理解问题、选工具、转述结果和概括非结构化内容（如课堂转录）。
2. **列表按用户最常问的顺序排好，并给出序号。** 截止列表最早的在前，课堂回放最近的在前；有歧义的“第一个”直接给出字段（如 `latest_started`）。
3. **约束放在服务端校验，不写进给模型看的 schema。** 发布的输入 schema 只保留字段、类型、枚举和默认值；数值上下限、正则、长度、数组大小由 `strictArgs` 按原始 zod shape 校验，违反时返回 `INVALID_ARGUMENT`。`$schema` 方言地址不发布。
4. **说明写一句话。** 工具说明只说做什么和关键参数；使用规则放进技能文档或结果的 `note`，不在每个工具里重复。
5. **错误同形。** 失败返回 `{code, message, ...}`，参数问题统一 `INVALID_ARGUMENT`；平台字段缺失报 `SCHEMA_CHANGED`，不把异常响应当空列表。

## lite（本地小模型）

- 工具按任务设计，一个问题尽量一两次调用答完；跨平台的同类数据（如各平台截止时间）合并成一个列表。
- 结果去掉 `null`、空数组、链接和元信息；正文分页，并在 `note` 里说明读多少就够、下一步用哪个工具、哪些操作不支持。
- 需要提醒的状态用布尔字段标出（如 `urgent`、`upcoming`、`overdue`），不让模型从时间字符串推断。
- 相同参数的重复读取直接提示模型回答，防止循环。
- 预算由测试锁定：工具目录 ≤6,000 字符，`skills/zju-lite/SKILL.md` ≤1.5 KB。

## full（标准版）

- 覆盖各平台的完整读写能力，但同样避免冗长：说明 ≤200 字，schema 按第 3 条精简。
- 预算由测试锁定：工具目录 ≤18,000 字符（2026-10-13 为 16,528，精简 schema 前为 26,716）。
